# Резервное копирование и восстановление

## Автоматические копии (ежедневно)

Если настроен `DISCORD_BACKUP_WEBHOOK_URL` и/или Google API, панель раз в сутки
(03:10 по `APP_TIMEZONE`) создаёт JSON-копию таблиц:

- сотрудники, формы, ответы форм, отчёты, документы, настройки;
- **секреты в копию не попадают**: URL вебхуков форм заменяются на `•••`
  (при восстановлении задайте их заново в конструкторе форм).

Копия отправляется:
- в Discord — JSON-файлом в канал резервных копий;
- в Google Drive — файлом `sheriff-panel-backup-<дата>.json` (если настроен Google).

День последней копии виден в «Настройки → Служебная информация».

## Копия файла базы (самый простой способ)

Вся база — один файл `data/panel.db`. Остановите сервер (или просто скопируйте —
SQLite переживёт копирование при небольшой нагрузке) и сохраните файл:
- локально: скопировать `data/panel.db` в надёжное место;
- на Railway: Volume → скачать через `railway ssh`/файловый менеджер, либо
  положиться на ежедневные JSON-копии.

Восстановление — положить файл обратно и запустить панель.

## Восстановление из JSON-копии

```bash
npm run setup                   # убедитесь, что база создана
RESTORE_ALLOW=true npm run restore -- путь/к/backup.json
```

Скрипт восстанавливает сотрудников, формы, ответы, отчёты и документы по их ID
(дубликаты не создаются). Поддерживаются копии обоих форматов (v1 и v2).
Пароли сотрудников в копии — хэши, они восстанавливаются как есть.
URL вебхуков форм из копии не переносятся (в копии они замаскированы) —
задайте их заново в конструкторе форм.

## Рекомендации

- Храните `SESSION_SECRET`, `ENCRYPTION_KEY` и `INTEGRATION_SHARED_SECRET` отдельно
  от копий (менеджер паролей). Без `ENCRYPTION_KEY` расшифровать вебхуки форм
  после переезда не получится — придётся ввести URL заново.
- Раз в месяц проверяйте, что копии реально приходят в Discord-канал.
- Смена `SESSION_SECRET` разлогинивает всех пользователей (сессии станут недействительны).
