# Известные ограничения

Честный список того, что требует внешних аккаунтов/ключей, что не проверено
и какие упрощения приняты в архитектуре.

## Требует внешних аккаунтов и ключей (без них функция показывает «Не настроено»)

| Функция | Что нужно |
|---------|-----------|
| Создание Google Форм и Документов | сервисный аккаунт + включённые Forms/Docs/Drive API ([GOOGLE-API.md](GOOGLE-API.md)) |
| Приём ответов форм | Apps Script в каждой форме + `INTEGRATION_SHARED_SECRET` ([APPS-SCRIPT.md](APPS-SCRIPT.md)) |
| Доставка в Discord | вебхуки: пер-формные и/или глобальные `DISCORD_*` ([DISCORD.md](DISCORD.md)) |
| Копии в Google Drive | тот же сервисный аккаунт |
| Копии в Discord | `DISCORD_BACKUP_WEBHOOK_URL` |

Ни одна из этих функций не имитируется: без ключей в UI отображается «Не настроено»,
endpoint возвращает 503, кнопки не создают фиктивных данных.

## Архитектурные ограничения

- **Один инстанс** — очередь DeliveryJob и планировщик копий рассчитаны на один
  процесс (Railway: не включайте горизонтальное масштабирование, иначе возможны
  параллельные отправки; дубли всё равно отсечёт `dedupeKey`).
- **Сессии в памяти процесса** — подписанный токен в cookie: перезапуск сервиса
  НЕ разлогинивает пользователей (токен самодостаточен до конца срока), но отзыв
  конкретной сессии невозможен. Разлогинить всех: сменить `SESSION_SECRET`.
- **Rate limit входа** — в памяти процесса; при рестарте счётчик сбрасывается.
- **Ответы форм** приходят только через Apps Script: формы, заполненные мимо
  триггера (импорт, ручное добавление через формы Google), в панель не попадают.
- **Файлы до 8 МБ** — лимит вложения Discord для резервных копий; при большом
  объёме базы используйте SQL-дамп (`pg_dump`).
- **Google Drive квоты** — копии и документы создаются от сервисного аккаунта;
  его Drive ограничен 15 ГБ, периодически чистите старые копии.

## Что проверено и что нет

**Проверено в этом окружении:**
- компиляция сервера (tsc) и клиента (vite build) — без ошибок;
- 19 unit-тестов: подпись/подделка сессий, AES-шифрование секретов, сборка
  Discord-embed (разбивка 1024, цвет, аватарка, footer), CSV с BOM, нормализация
  никнеймов, экспоненциальный backoff очереди;
- запуск сервера: health-endpoint, CSRF-cookie, отказ POST без CSRF (403),
  отказ ingest без секрета (401), отказ закрытого API без сессии (401),
  раздача собранного фронтенда;
- prisma validate + генерация SQL-миграции.

**Не проверено здесь (нет внешних аккаунтов), проверяется по инструкциям после деплоя:**
- реальные вызовы Google Forms/Docs/Drive API;
- приём ответа от реального Apps Script и доставка в реальный Discord;
- деплой Railway с PostgreSQL;
- e-mail/пуш-уведомления — их в системе нет сознательно (только уведомления в панели).

## Принципы безопасности

- секреты только в переменных окружения, в репозитории — `.env.example` без значений;
- URL вебхуков в БД — AES-256-GCM (`ENCRYPTION_KEY`/`SESSION_SECRET`), наружу — маска;
- пароли — bcrypt (10 раундов), проверка прав на сервере для каждого endpoint;
- аудит-лог не содержит секретов (маскируются ключи `password|secret|token|url|key`).
